# XAI 보고서: SHAP 전역·지역 해석과 거절 사유

> 교육용으로만 사용합니다. 실제 금융 의사결정에 사용하지 마십시오. 대안 데이터는 시뮬레이션 값이며, 시뮬레이터가 모든 행에 타깃을 사용하므로 대안 변수의 영향은 실제보다 큽니다.

- 대상: 배포 모델 (`models/xgboost_v1.0.joblib`, XGBoost, 변수 21개, 단조 제약 13개). 전역 해석은 **test 세트** 22,500명.
- 코드: `src/explainer/shap_explainer.py` (TreeExplainer), `src/explainer/global_shap.py` (전역 그림), `src/explainer/reasons.py` (거절 사유 문장). 설정: `configs/config.yaml`의 `explainer`.
- 실행: `python -m src.explainer.global_shap` (한글 폰트 전달 방법은 README 참고). API: `POST /explain` (지역 해석, 거절 사유), `GET /explain/global` (전역 Top 10). 대시보드: "XAI 분석" 탭 (Waterfall).
- 그림: `reports/figures/13_shap_summary_{ko,en}.png`, `reports/figures/14_shap_dependence_{ko,en}.png`.

## 1. SHAP이란

SHAP은 모델의 예측 하나를 **변수별 기여도의 합**으로 나눕니다.

```
모델 출력 (부도 log-odds) = 기준값 + 변수1의 SHAP + 변수2의 SHAP + ... + 변수21의 SHAP
```

- **기준값** (base value) = −2.675. 학습 데이터 평균 신청자의 log-odds이며, 부도 확률로는 약 6.4%입니다.
- **SHAP 값이 양수**면 그 변수가 부도 위험을 높였다는 뜻이고 (거절 쪽), **음수**면 낮췄다는 뜻입니다 (승인 쪽).
- 합이 정확히 모델 출력과 같으므로, 설명과 실제 판정이 어긋나지 않습니다. log-odds를 부도 확률로 바꾸고, 다시 점수로 바꾸면 승인 여부가 나옵니다 (`configs/scoring.yaml`).
- XGBoost 같은 트리 모델에는 **TreeExplainer**가 정확한 SHAP 값을 빠르게 계산합니다 (22,500명에 몇 초).

## 2. 전역 해석: 모델은 무엇을 중요하게 보는가

### 2.1 Summary Plot (`13_shap_summary_ko.png`)

점 하나가 신청자 한 명입니다. **가로 위치**는 그 변수의 SHAP 값 (오른쪽 = 위험 증가), **색**은 그 변수의 값 (주황 = 높음, 파랑 = 낮음, 회색 = 결측)입니다. 변수는 평균 |SHAP|이 큰 순서로 위에서부터 15개를 보여줍니다.

| 순위 | 변수 | 평균 \|SHAP\| | 조치 가능성 |
|---|---|---|---|
| 1 | 앱 로그인 빈도 | 0.671 | 권장 불가 |
| 2 | 정기결제 건수 | 0.553 | 권장 불가 |
| 3 | 소비 일관성 점수 | 0.528 | 조치 가능 |
| 4 | 통신사 가입 유지 기간 | 0.469 | 시간 의존 |
| 5 | 건강보험·국민연금 납부 개월수 | 0.452 | 시간 의존 |
| 6 | 리볼빙 한도 사용률 | 0.415 | 조치 가능 |
| 7 | 90일 이상 연체 횟수 | 0.216 | 감소 불가 |
| 8 | 연령 | 0.214 | 불변 (보호 속성) |
| 9 | 30~59일 연체 횟수 | 0.204 | 감소 불가 |
| 10 | 통신요금 정시납부율 | 0.152 | 조치 가능 |

(11~15위: 공과금 정시납부율, 60~89일 연체 횟수, 보유 대출·신용한도 수, 부채비율, 부동산 담보대출 수.)

**읽는 법과 발견:**
1. **상위 5개가 모두 대안 변수입니다.** 시뮬레이터가 과제 규칙에 따라 이 변수들을 부도와 강하게 연결했기 때문입니다 (과제 변수는 각각 단독으로 AUC 0.80~0.84). 실제 대안 데이터라면 이보다 약할 수 있습니다.
2. **색의 방향이 상식과 맞습니다.** 앱 로그인, 정기결제, 소비 일관성, 납부 개월수는 값이 높을수록 (주황) 왼쪽, 즉 위험이 낮습니다. 사용률, 연체, 부채비율은 값이 높을수록 오른쪽입니다.
3. **1·2위는 "권장 불가" 변수입니다.** 모델에는 중요하지만, 신청자에게 "로그인을 늘리라"고 조언하면 점수를 조작하는 행동을 부추깁니다. 그래서 거절 사유에는 "참고(변경 불가)"로만 표시하고, 승인 경로 (DiCE)에서는 바꾸지 않습니다.
4. **연체 변수는 "있다/없다"가 결정적입니다.** 연체가 없으면 (회색) 0 근처에 몰려 있고, 1회라도 있으면 (주황) +0.5 이상 떨어져 있습니다.

한 변수의 값 (가로)에 따라 SHAP 값 (세로)이 어떻게 바뀌는지 보여줍니다. 4개 변수는 `explainer.dependence_features`에서 고릅니다: 조치 가능 변수 1위, 대표 전통 신용 변수, 보호 속성, 단조 제약 연체 변수.

| 변수 | 모양 | 의미 |

| 리볼빙 한도 사용률 | 0에서 −0.5, 1 (100%)에서 +0.5. 꾸준히 증가 | 단조 제약 (+1)이 지켜짐. 0.3, 0.5 부근에서 계단이 생기는 것은 트리 모델의 분할 지점 때문 |
| 연령 | 20~30대 약 +0.25, 나이가 들수록 감소, 70대에서 약 −0.5, 80대 이후 다시 약간 상승 | 단조 제약이 없음 (보호 속성). **젊은 신청자의 점수를 직접 낮추며, 이것이 공정성 보고서의 연령대 EO 격차의 원인입니다** (`reports/fairness_report_ko.md`) |
| 90일 이상 연체 횟수 | 0회 약 −0.2, 1회 +0.8 ~ +1.2, 4회 이상 약 +1.5 | 단조 제약 (+1)이 지켜짐. 첫 연체가 가장 큰 영향을 주고, 이후는 완만하게 증가 |

## 3. 지역 해석: 이 신청자는 왜 거절됐는가

`POST /explain`은 신청자 한 명의 SHAP 값을 계산합니다. 대시보드는 이것을 **Waterfall Plot**으로 그립니다. 기준값에서 시작해 변수별 SHAP 값을 하나씩 더해 가며 최종 log-odds에 도착하는 막대 그림입니다. 막대가 오른쪽 (빨강)이면 위험을 높인 변수, 왼쪽 (초록)이면 낮춘 변수입니다.

아래는 test 세트에서 고른 실제 거절자 2명의 API 응답입니다 (정제 플래그가 없는 신청자, 모델 점수와 API 점수 일치 확인).

### 신청자 A: 씬파일러, 연체 없음, 점수 466 (D등급, 부도 확률 11.3%)

주요 값: 연령 34세, 리볼빙 사용률 100%, 보유 대출·신용한도 2개, 부동산 담보대출 0개 (씬파일러), 건강보험 납부 14개월, 통신사 가입 17개월, 소비 일관성 71.4점, 공과금 정시납부율 58%.

| 변수 | SHAP | 방향 |
|---|---|---|
| 건강보험·국민연금 납부 개월수 (14개월) | +0.613 | 위험 증가 |
| 리볼빙 한도 사용률 (100%) | +0.608 | 위험 증가 |
| 소비 일관성 점수 (71.4) | −0.269 | 위험 감소 |
| 통신사 가입 유지 기간 (17개월) | +0.252 | 위험 증가 |
| 연령 (34세) | +0.240 | 위험 증가 |
| 앱 로그인 빈도 (22회) | −0.195 | 위험 감소 |
| 보유 대출·신용한도 수 (2개) | −0.191 | 위험 감소 |
| 90일 이상 연체 횟수 (0회) | −0.171 | 위험 감소 |

기준값 −2.675 + SHAP 합계 +0.616 = −2.059 (부도 확률 11.3%, 점수 466). 승인선 475에 9점 모자랍니다.

## 4. 거절 사유 자동 생성

`src/explainer/reasons.py`가 SHAP 값으로 거절 사유를 만듭니다.

1. 부도 위험을 높인 변수 (SHAP ≥ 0.01, `rejection_reason_min_contribution`)만 고릅니다.
2. SHAP 값이 큰 순서로 최대 5개 (`rejection_reasons_top_k`)를 고릅니다.
3. 각 변수를 문장으로 만듭니다: 변수 이름, 현재 값, **학습 데이터 중앙값과의 비교**, 기여도. 값 표시 형식 (%, 회, 개월, 원)과 한국어 조사 (이/가, 으로/로)는 자동으로 맞춥니다.
4. 기여도는 과제 예시처럼 **승인 방향 기준**으로 표시합니다 (= −SHAP, 음수 = 거절 쪽).
5. 신청자가 바꾸면 안 되거나 바꿀 수 없는 변수 ("권장 불가", "불변", "감소 불가" 분류, `explainer.reference_only_classes`)에는 "[참고(변경 불가)]"를 붙입니다. 조언이 아니라 참고 정보라는 뜻입니다. 조치 가능 변수와 시간 의존 변수에는 붙이지 않습니다.

**신청자 A의 거절 사유 (API 응답 그대로):**

1. 건강보험·국민연금 납부 개월수가 14개월로, 학습 데이터 중앙값(18개월) 대비 짧습니다 (기여도: -0.61)
2. 리볼빙 한도 사용률이 100%로, 학습 데이터 중앙값(15%) 대비 높습니다 (기여도: -0.61)
3. 통신사 가입 유지 기간이 17개월로, 학습 데이터 중앙값(40개월) 대비 짧습니다 (기여도: -0.25)
4. 연령이 34세로, 학습 데이터 중앙값(52세) 대비 낮습니다 (기여도: -0.24) [참고(변경 불가)]
5. 공과금(전기·가스·수도) 정시납부율이 58%로, 학습 데이터 중앙값(83%) 대비 낮습니다 (기여도: -0.13)

**신청자 B의 거절 사유:**

1. 90일 이상 연체 횟수가 1회로, 학습 데이터 중앙값(0회) 대비 많습니다 (기여도: -0.97) [참고(변경 불가)]
2. 앱 로그인 빈도가 19회로, 학습 데이터 중앙값(23회) 대비 적습니다 (기여도: -0.74) [참고(변경 불가)]
3. 소비 일관성 점수가 48.8점으로, 학습 데이터 중앙값(73.6점) 대비 낮습니다 (기여도: -0.47)
4. 리볼빙 한도 사용률이 73%로, 학습 데이터 중앙값(15%) 대비 높습니다 (기여도: -0.43)
5. 연령이 33세로, 학습 데이터 중앙값(52세) 대비 낮습니다 (기여도: -0.17) [참고(변경 불가)]

**해석:**
- 신청자 A는 연체가 없지만, 신용 이력이 짧고 (납부 14개월, 통신 17개월) 카드 한도를 모두 쓰고 있어 거절됐습니다. 씬파일러가 거절되는 전형적인 모습입니다. 사용률을 낮추면 바로 개선할 수 있고, 납부 개월수와 가입 기간은 시간이 지나면 개선됩니다.
- 신청자 B는 과거 연체 1회가 가장 큰 이유이며, 이것은 줄일 수 없습니다. 납부 이력은 길어서 (21개월, 80개월) 위험을 크게 낮췄지만, 연체와 낮은 소비 일관성을 넘지 못했습니다.
- 두 신청자 모두 거절 사유에 **연령**이 나옵니다. 2.2절의 연령 효과가 개인 수준에서도 나타나는 것입니다.

## 5. 한계와 남은 과제

- **대안 변수의 영향이 과장되어 있습니다.** 시뮬레이터가 실제 부도 여부로 대안 변수를 만들었으므로, 상위 5개가 모두 대안 변수인 것은 시뮬레이션 설계의 결과입니다.
- **SHAP은 상관이지 인과가 아닙니다.** "소비 일관성을 올리면 점수가 오른다"는 모델 기준으로는 맞지만, 실제로 그 행동이 부도 위험을 낮추는지는 보장하지 않습니다.
- **비교 기준은 학습 데이터 중앙값입니다.** "중앙값 대비 높다/낮다"는 문장은 비교 대상을 알려줄 뿐, 그 값이 나쁘다는 판단은 SHAP 기여도가 합니다.
- **바꿀 수 없는 사유도 보여줍니다.** 연령이나 과거 연체처럼 신청자가 바꿀 수 없는 변수도 거절의 실제 이유이므로 숨기지 않고 "[참고(변경 불가)]"로 표시합니다. 신청자는 거절 이유를 정확히 알 수 있지만, 조치할 수 있는 사유는 그보다 적을 수 있습니다 (신청자 B는 5개 중 2개).
- 시간 의존 변수 (납부 개월수, 가입 기간)는 행동이 아니라 기다리는 기간으로 안내해야 합니다. 현재 거절 사유 문장은 사실만 서술하므로 문제는 없지만, 승인 경로 (DiCE) 문구에서는 이 규칙을 지켜야 합니다.
