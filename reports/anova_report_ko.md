# ANOVA 통계 검증 보고서

> 교육용으로만 사용합니다. 실제 금융 의사결정에 사용하지 마십시오. 대안 데이터는 시뮬레이션 값이며, 시뮬레이터가 모든 행에 타깃을 사용하므로 대안 데이터를 쓴 AUC는 낙관적입니다.

- 코드: `src/statistics/anova.py` (One-way ANOVA, η², Tukey HSD). 테스트: `tests/test_reasons_and_anova.py`, `tests/test_api_endpoints.py`.
- 검증 정의: `configs/config.yaml`의 `statistics.anova` (집단 열, 필터, 라벨). 유의수준 α = 0.05, η² 기준 0.01 / 0.06 / 0.14 (작음 / 중간 / 큼).
- 입력: `reports/cv_fold_auc.csv` (데이터 설명은 `reports/anova_handoff_ko.md`). API: `GET /anova`. 대시보드: "통계 검증" 탭.

## 요약

| 검증 | 질문 | F | p | η² | 결론 |
|---|---|---|---|---|---|
| 1. 피처 그룹별 | 대안 데이터를 쓰면 AUC가 달라지는가 | 17,086 | < 0.001 | **0.981 (큼)** | 세 그룹 모두 다름. 통합 > 대안 > 전통 |
| 2. 알고리즘별 (통합 피처) | 어떤 알고리즘이 나은가 | 11.8 | < 0.001 | 0.096 (중간) | 트리 모델 2개가 LR보다 0.002 높음. XGBoost와 LightGBM은 차이 없음 |

두 검증 모두 p < 0.05이므로 Tukey HSD 사후 검정을 수행했습니다.

## 1. 방법

**ANOVA (분산분석)** 는 세 개 이상 집단의 평균이 우연 이상으로 다른지 판정합니다.

| 값 | 의미 |
|---|---|
| F 통계량 | 집단 사이 차이 ÷ 집단 안의 흔들림. 클수록 차이가 확실함 |
| p-value | 실제로는 차이가 없을 때 이만큼 차이가 날 확률. 0.05 미만이면 유의미 |
| η² (에타 제곱) | 전체 변동 중 집단 차이로 설명되는 비율. 차이가 "얼마나 큰지"를 나타냄 |
| Tukey HSD | ANOVA가 유의미할 때, 어느 집단 쌍이 다른지 확인. 여러 쌍을 비교할 때 생기는 오류를 보정함 |

p-value는 "차이가 있는가"를, η²는 "차이가 얼마나 큰가"를 답합니다. 표본이 많으면 아주 작은 차이도 p < 0.05가 되므로 둘을 함께 봐야 합니다.

**데이터:** train 분할 안에서 층화 5겹 교차검증을 5번 반복해 얻은 폴드별 AUC입니다. 실행 27개 = 알고리즘 3개 (LR, XGBoost, LightGBM) × 피처 그룹 3개 (전통 Only, 대안 Only, 통합) × 불균형 처리 3개 (없음, class_weight, SMOTE). 실행마다 AUC 25개 (5회 × 5겹)이며, 모든 실행이 같은 폴드를 씁니다. 두 검증 모두 전체 검증 행 (`segment = all`)을 사용합니다.

## 2. 검증 1: 피처 그룹별 AUC

**설계:** 집단 = 피처 그룹. 집단마다 알고리즘 3개 × 불균형 처리 3개 × 25 = 225개 AUC.

| 피처 그룹 | 개수 | 평균 AUC | 표준편차 |
|---|---|---|---|
| 전통 Only (GMSC 변수만) | 225 | 0.8572 | 0.0069 |
| 대안 Only (대안 변수만) | 225 | 0.9124 | 0.0038 |
| 통합 (둘 다) | 225 | **0.9408** | 0.0031 |

**ANOVA:** F = 17,086, p < 0.001, η² = 0.981 (큼).

**Tukey HSD:**

| 비교 | 평균 차이 | 95% 신뢰구간 | 보정 p | 유의미 |
|---|---|---|---|---|
| 통합 − 전통 Only | +0.0836 | 0.0825 ~ 0.0847 | < 0.001 | 예 |
| 통합 − 대안 Only | +0.0284 | 0.0273 ~ 0.0294 | < 0.001 | 예 |
| 대안 Only − 전통 Only | +0.0552 | 0.0542 ~ 0.0563 | < 0.001 | 예 |

## 3. 검증 2: 알고리즘별 AUC (통합 피처)

**설계:** 집단 = 알고리즘. **통합 피처 실행만** 사용합니다. 집단마다 불균형 처리 3개 × 25 = 75개 AUC.

**통합 피처로 좁힌 이유:** 피처 그룹을 섞으면 각 알고리즘 집단 안에 AUC 0.86 (전통)부터 0.94 (통합)까지 섞입니다. 이 큰 차이가 "집단 안의 흔들림"으로 잡혀서 알고리즘 사이의 작은 차이를 가립니다. 실제로 섞어서 검정하면 F = 0.16, p = 0.85, η² = 0.0005로 "차이 없음"이 나옵니다. 아래 표처럼 같은 피처 그룹 안에서는 알고리즘 차이가 일정하게 보이므로, 이 결론은 설계 때문에 생긴 착시입니다. 최종 모델이 통합 피처를 쓰므로, 통합 피처에서의 비교가 "최종 모델에 어떤 알고리즘을 쓸까"라는 질문에 맞습니다.

| 평균 AUC | 전통 Only | 대안 Only | 통합 |
|---|---|---|---|
| LR | 0.853 | 0.914 | 0.939 |
| XGBoost | 0.859 | 0.912 | 0.942 |
| LightGBM | 0.859 | 0.911 | 0.941 |

| 알고리즘 | 개수 | 평균 AUC (통합) |
|---|---|---|
| LogisticRegression | 75 | 0.9394 |
| XGBoost | 75 | **0.9415** |
| LightGBM | 75 | 0.9414 |

**ANOVA:** F = 11.8, p = 0.00001, η² = 0.096 (중간).

**Tukey HSD:**

| 비교 | 평균 차이 | 95% 신뢰구간 | 보정 p | 유의미 |
|---|---|---|---|---|
| XGBoost − LR | +0.0021 | 0.0009 ~ 0.0032 | < 0.001 | 예 |
| LightGBM − LR | +0.0020 | 0.0008 ~ 0.0031 | < 0.001 | 예 |
| XGBoost − LightGBM | +0.0001 | −0.0010 ~ 0.0012 | 0.971 | 아니오 |

## 4. 해석

**검증 1: 대안 데이터의 효과는 크고 확실합니다.** 전통 변수에 대안 변수를 더하면 AUC가 평균 0.084 오릅니다 (0.857 → 0.941). η² = 0.98은 AUC 변동의 98%가 피처 그룹으로 설명된다는 뜻입니다. 알고리즘이나 불균형 처리를 바꾸는 것보다 어떤 데이터를 쓰는지가 훨씬 중요합니다. 대안 변수만으로도 전통 변수만 쓸 때보다 AUC가 0.055 높습니다. 두 데이터를 합친 통합이 대안 Only보다도 0.028 높으므로, 두 데이터는 서로를 대체하지 않고 보완합니다.

다만 이 크기는 낙관적입니다. 시뮬레이터가 실제 부도 여부를 보고 대안 변수를 만들기 때문에 (과제 예시와 같은 방식), 과제 변수 각각이 단독으로 AUC 0.80~0.84에 이릅니다. 현실적인 기준은 전통 Only의 0.857입니다. 이 검증은 "시뮬레이션 설계대로 대안 데이터가 정보를 더한다"는 것을 확인할 뿐, 실제 대안 데이터의 효과를 보여주지는 않습니다.

**검증 2: 알고리즘 차이는 유의미하지만 작습니다.** 트리 기반 모델 (XGBoost, LightGBM)이 LR보다 AUC가 약 0.002 높고, 두 트리 모델 사이에는 차이가 없습니다. η² = 0.096은 통합 피처 안에서 AUC 변동의 약 10%를 알고리즘이 설명한다는 뜻입니다. 그러나 AUC 0.002는 검증 1의 효과 (0.084)의 40분의 1이고, 실무적으로 거의 구별되지 않는 차이입니다. 최종 모델 XGBoost는 학습 코드의 선정 규칙 (통합 피처 실행 중 AUC 최고, `configs/train.yaml`)으로 뽑혔습니다. **이 검증은 그 선택이 LR보다 낫다는 것을 통계적으로 뒷받침하지만, LightGBM과는 차이가 없어 둘 중 어느 것을 써도 성능은 같습니다.** LR을 썼어도 성능 손실은 작았을 것입니다.

**p-value와 효과 크기:** 두 검증 모두 p < 0.001이지만 차이의 크기는 40배 다릅니다. 표본이 많으면 아주 작은 차이도 유의미해지므로, 의사결정에는 p-value보다 평균 차이와 η²가 중요합니다.

**검증 설계의 교훈:** 같은 데이터라도 무엇을 섞어서 비교하느냐에 따라 결론이 뒤집힙니다 (검증 2: p = 0.85 → p = 0.00001). 큰 효과를 내는 요인 (여기서는 피처 그룹)은 고정하고 비교해야 작은 효과를 공정하게 볼 수 있습니다.

## 5. 한계

- **폴드 AUC는 독립 표본이 아닙니다.** 5겹 교차검증의 폴드들은 학습 데이터의 대부분을 공유하고, 5번의 반복도 같은 train 데이터를 다시 나눈 것입니다. ANOVA는 독립 표본을 가정하므로 p-value는 근사값이며 보통 실제보다 작게 나옵니다. 검증 1은 효과가 매우 커서 결론이 바뀌지 않지만, 검증 2의 p-value는 신중하게 해석해야 합니다.
- **모든 실행이 같은 폴드를 씁니다.** 같은 폴드끼리 짝지어 비교하는 반복측정 설계 (예: 폴드를 블록으로 둔 분석)가 더 정확하지만, 과제 요구사항 (One-way ANOVA)에 맞춰 일원 분석을 사용했습니다.
- **검증 2는 불균형 처리 3종을 섞습니다.** 불균형 처리에 따른 AUC 차이는 0.002 이하로 작지만, 집단 안의 흔들림에 포함됩니다. 최종 설정 (불균형 처리 없음)만 쓰면 F = 7.6, p = 0.001, η² = 0.17로 결론은 같습니다.
- 모든 AUC는 train 분할 안의 교차검증 값입니다. 공식 성능은 test 세트 결과 (`reports/model_report_ko.md`)를 참고하십시오.
